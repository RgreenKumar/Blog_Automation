# Media Jungle — Dynamic Blog CMS (PHP + MySQL)

This package converts the 3 hardcoded blog cards on your homepage into a
database-driven blog system, **without changing any visual design**. Layout,
fonts, colors, spacing, animations, header, footer, and every existing CSS
class are untouched — only the blog card markup is now generated by PHP
instead of being typed by hand, and a "Previous 1 2 3 Next" pagination
control (styled to match your dark theme) was added below the cards.

## What's in this package

```
config.php                 Database connection + upload settings
index.php                  Your homepage (was index.html) — blog section is now dynamic
uploadblog.php              Upload form: add a new blog post
upload_blog_process.php     Handles the form submission securely
includes/functions.php      Pagination query, secure file upload, HTML escaping
includes/csrf.php           CSRF token helpers used by the upload form
database/schema.sql         Creates the `blogs` table + seeds your existing 3 posts
uploads/blog_images/        Thumbnails land here
uploads/blog_html/          Uploaded article HTML files land here
uploads/.htaccess           Blocks PHP execution inside /uploads (security)
```

## 1. Install

1. Copy every file above into your live project, alongside `blogmj.html`,
   `pricing.html`, `download.html`, etc. (Your original `index.html` is
   replaced by `index.php` — remove or rename the old `index.html` so your
   web server serves `index.php` as the homepage; most servers already
   prefer `index.php` automatically once both exist, but check your
   `DirectoryIndex`/hosting panel setting.)
2. Make sure `uploads/blog_images/` and `uploads/blog_html/` are writable
   by the web server (`chmod 755` is normally enough; use `775`/correct
   ownership if your host requires it).

## 2. Create the database

Import the schema (creates the `blogs` table and inserts your current 3
posts so the site looks identical the moment you go live):

```bash
mysql -u your_db_user -p your_database_name < database/schema.sql
```

If you already have a database you want to reuse, open `database/schema.sql`
and remove the `CREATE DATABASE` / `USE` lines first.

## 3. Configure `config.php`

Open `config.php` and edit the **"EDIT THESE"** sections:

```php
const DB_HOST = 'localhost';
const DB_NAME = 'mediajungle_blog';
const DB_USER = 'your_db_user';
const DB_PASS = 'your_db_password';
```

## 4. Add a blog post

1. Go to `https://yourdomain.com/uploadblog.php`.

   > ⚠️ **No login is required to reach this page in this package.**
   > Anyone with the URL can upload a blog post. If that's not what you
   > want, add your own access check (session login, `.htaccess` password,
   > IP allowlist, or your existing admin system) at the top of
   > `uploadblog.php` and `upload_blog_process.php` before going live —
   > just say the word and I can add a simple login gate back in.

2. Fill in:
   - Thumbnail (JPG/PNG/WEBP, max 5MB)
   - Blog Title
   - Blog Description (shown on the card)
   - HTML file (.html/.htm, max 2MB) — this is what opens when someone
     clicks "5 MIN READ"
   - Publish Date
3. Submit. You'll see "Blog uploaded successfully," and the post
   immediately appears as the newest card on the homepage.

## How it works

- **Listing (`index.php`)** runs `SELECT ... FROM blogs ORDER BY created_at
  DESC` and loops over the results to print the exact same card markup that
  used to be hardcoded — same classes, same structure, same `data-aos`
  attributes.
- **Pagination** shows 3 blogs per page. The "Previous 1 2 3 4 Next" control
  is generated by `render_pagination()` in `includes/functions.php`, and is
  styled with a small scoped `<style>` block (added, not modifying your
  existing CSS files) so it matches the dark/purple color scheme already on
  the page.
- **Security**: all database queries use PDO prepared statements (no SQL
  injection), all dynamic text is passed through `htmlspecialchars()` before
  being echoed (no XSS), uploaded files are validated by real MIME type
  (not just the filename extension), given random unguessable filenames, and
  `/uploads` blocks PHP execution via `.htaccess`.

## Extending later (Edit/Delete)

The `blogs` table and `id` primary key are already CRUD-ready. To add
Edit/Delete, you'd create `edit_blog.php` / `delete_blog.php` following the
same pattern as `upload_blog_process.php` (require_admin → verify CSRF token
→ prepared statement). Not included here since it wasn't part of the
original scope, but the structure supports it directly.

## Notes

- The homepage's Nav, Hero, About, Pricing, footer, contact form, etc. are
  byte-for-byte the same as your original `index.html` — only the blog
  section (between `<section id="blog">` and its closing `</section>`) was
  changed.
- The 3 existing posts were seeded with `html_file` values pointing at
  `blogmj.html#ownership`, `#scalability`, and `#launch-guide` — exactly
  where they point today — so nothing breaks on day one. Every *new* post
  you upload will point at its own file under `uploads/blog_html/`.
